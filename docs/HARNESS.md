## What I'd change in the harness
Written during M4 (before Gate 3) from the M1–M4 notes below. An item that would change a protected path (`.claude/protected-paths.txt`) ends with "(Protected: …)" naming the paths; those items (1–5) are proposals for the architect, not changes made here. Items 6–9 need no protected-path change.

1. **Verify agent reports against GitHub and the tree, by rule.** The worst M1–M3 defects were reports that were wrong, not code: a reviewer's label and comment that never reached GitHub (M1), a hand-back that was the word "placeholder" (M2), test counts from the wrong tree (M3, twice), and a results row that missed a LIVE/REPLAY difference (M4). The merge check (label + verdict comment on GitHub) caught the first two. I'd make the rest mechanical: reviewers quote the PR head SHA and run in the PR's worktree, and every number a report cites is re-derived by a test (as `tests/test_readme.py` and `tests/test_demo_doc.py` now do for README and DEMO.md). (Protected: `.claude/agents/reviewer.md`, `.claude/agents/orchestrator.md`.)
2. **Only the orchestrator writes STATE.md, and does it once per merge.** Builders and the orchestrator both edited it in M1, and reviewers blocked on it in M2 because the definition of done doesn't say who writes it. Since then it has cost one small orchestrator PR per merge (8 in M3, 4 in M4) and an extra CI run each. Batching the STATE.md rewrite into the merge commit, or into one PR per milestone, would remove most of that churn. (Protected: `CLAUDE.md` definition of done, `.claude/agents/orchestrator.md`.)
3. **Make DECISIONS-LOG.md append-only by section, or one file per issue.** Every PR appends to it, so parallel PRs conflict (#66) and builders rebase just before pushing. A `decisions/<issue>.md` per issue, concatenated at milestone close, would not conflict. (Protected: `docs/HARNESS_DESIGN.md` §6.7, `CLAUDE.md`, `.claude/agents/*`.)
4. **Narrow the worktree guard.** It refuses any command containing "eval", even in paths (`ls eval/`), and any chained or heredoc command. That cost a re-run on almost every M3 and M4 issue and pushed one M3 builder to wrapper scripts and a copied `.redaction-denylist`. The guard should match the command being run (for example a shell `eval` builtin), not a substring, and there should be a sanctioned way to run the redaction check in a worktree. (Protected: `.claude/settings.json`, `.claude/hooks/*`.)
5. **Stop label events re-triggering CI.** `protected-paths` listens to label events, so adding `reviewer-approved` restarts CI before every merge. Running that job on `pull_request` code events only, and checking labels at merge time, saves one CI cycle per PR. (Protected: `.github/workflows/*`.)
6. **Issue file lists should include the usual extras.** DECISIONS-LOG.md, the test file for a docs or data issue, shared helpers and recording drivers were missing from almost every issue's list (M3 note 7; #24, #27 and this issue each added a test file). The planner template should add them by default so that disclosures mark real surprises.
7. **Pin outcomes, not tuned values.** The S2.9 test broke because it pinned a tuned cut-off that moved when the data grew. Tests for tuned values should check "the frozen value is still optimal", so data growth doesn't force a test edit under invariant 6.
8. **Record the metrics the harness can't see as it goes.** Agent token spend and architect minutes are UNKNOWN in every row because nobody logs them during the run. A one-line entry per gate (architect minutes) and per dispatched agent (tokens from `/cost`), appended to this file by whoever can see them, would close the two empty columns.
9. **Cite sources that exist.** PLAN §S4.1 and #24 cite START_HERE, which isn't in the repo. Issue templates should link only to files on main.

## M1 notes (orchestrator)
Harness defects found in the M1 run, and the fix applied:
1. **Reviewer reported actions that never reached GitHub (PR #40).** The reviewer said it had added `reviewer-approved` and a comment; neither existed, and the orchestrator merged on the report. Fix: the merge step now checks GitHub for the label *and* a verdict comment, and reviewer briefs ask it to re-read the PR after each gh write. A post-merge review approved #40 with no required fixes.
2. **Key validity not checked at start.** The orchestrator checked that `ANTHROPIC_API_KEY` was set, not that it was real (it was a 3-char placeholder), so S1.5 blocked mid-run. Fix: the architect's env-file rule (DECISIONS-LOG); check by length only, never by value.
3. **Personal path leaked into public docs** (STATE.md via PR #38, DECISIONS-LOG via PR #39) when copying the architect's instruction. Caught by the reviewer on #39 and fixed. Fix: committed text uses `<repo-root>`; builder briefs say so.
4. **Builders and the orchestrator both rewrite STATE.md**, which causes merge conflicts across parallel PRs. The orchestrator overwrites it on the PR branch before merging (one extra CI run per issue). Worth simplifying: builders should leave STATE.md alone.
5. **Labels re-trigger CI** (`protected-paths` listens to label events), so reviewers often saw "pending" jobs. Harmless, but merges wait for the re-run.
6. **Environment:** builder sandboxes refused shell commands containing the word "eval"; an orchestrator scratch worktree was deleted externally mid-run.

## M2 notes (orchestrator)
1. **Reviewers blocked on STATE.md** (PR #45, two rounds) because CLAUDE.md's definition of done doesn't say who rewrites it. Fix: DECISIONS-LOG row (orchestrator writes it at merge) and reviewer briefs say so; the CLAUDE.md wording is for the architect (protected).
2. **Agent-cited IDs can be wrong.** The S2.2 data-author listed uncertain cases by patient-ref numbers, not case IDs. Fix: the orchestrator verifies every cited case ID against the file before it goes into a packet.
3. **A reviewer's hand-back was the literal word "placeholder"** (PR #48). The M1 merge check (label + verdict comment on GitHub) showed the review had happened; the merge went on that evidence, not the report.
4. **PR-number-only reviewer briefs miss orchestrator concerns.** Reviewers didn't address the baseline-flag SPEC divergence (#48) or `ModelClient._live` (#50). The orchestrator checked both itself and queued them for Gate 2. Worth considering: let the orchestrator attach a "check also" list without its conclusions.
5. **Inferred dependencies:** #13 started before S2.2 with its merge held; that worked and kept the code lane busy, at the cost of one extra builder round-trip after S2.2 landed.
6. **Permission denial not proxied:** the S2.4 builder was denied `gh issue` writes and asked the orchestrator to make them; it refused and raised the denial for the architect.
7. **Environment:** label events still re-trigger CI (an extra run before every merge); the auto-mode classifier rejected some backgrounded commands after a directory change until they were re-issued unchanged.

8. **S2.9 (#53): a data change forced a test change.** The new dev cases moved the baseline cut-off plateau midpoint from 0.80 to 0.79, so the data-author rewrote a pinned test. The reviewer flagged it under invariant 6. The orchestrator didn't loop the data-author: the only "fixes" were weakening the test or fitting the data to it. It escalated to the architect in session, who accepted the change, recorded on the issue and in DECISIONS-LOG. Lesson: tests that pin a tuned value to a re-derivation break whenever the data grows; they should pin "the frozen value is still optimal". 1 round, 4 live calls.

## M3 notes (orchestrator)
1. **Data-lane PRs need code-lane tests.** The data-author can't write tests, and the reviewer required them for new fixtures (#61). A builder added `tests/test_demo_fixtures.py` on the same branch and the data-author fixed the data, with each role kept to its own files. The test found a real top-score tie in the unsafe demo case, which was replaced by a clear match. Lesson: data issues that assert outcomes should list a test file and a code-lane helper from the start.
2. **Split ACs need a parent note.** `make demo` needed a CLI and live recordings, so it moved from #23 to #62. The reviewer then asked again for the split to be recorded on #23. The orchestrator now edits the parent AC to point at the child issue at the moment it splits.
3. **Stop-and-ask worked (#56).** The builder stopped on the orchestrator's stop condition: M-01 recall fell, but only for the baseline, and as a direct result of the AC. It listed four knock-on failures and changed nothing. The orchestrator decided each one: accept the baseline drop, re-record 9 explanations, change two test fixtures with identical assertions per amended SPEC §6, and regenerate the tuning proposal. The reviewer confirmed nothing was loosened. **For the architect:** the two fixture changes in tests/test_rules.py are an orchestrator call under invariant 6; please confirm.
4. **The worktree guard catches the word "eval"** in commands and even in paths (`ls eval/`, `grep … eval/`), and also catches chained or heredoc commands. The #21 builder got around it with wrapper scripts and copied the gitignored `.redaction-denylist` into its worktree (the orchestrator deleted the copy). From #22 on, builders were told to report blocks rather than work around them, and all did. **For the architect:** narrow the guard pattern (it's in protected settings) and decide how worktrees should run the redaction check locally.
5. **Reviewers often skip local runs, and twice ran on the wrong tree.** The #77 reviewer reported 711 tests where the PR had 763, and the #81 reviewer first ran main. The orchestrator re-ran #77's suite itself before merging. CI covers this, but a reviewer's "I ran it" can be wrong. Suggestion: the reviewer brief should require running in the PR's worktree and quoting the head SHA.
6. **Merge mechanics:** a plain `gh pr merge --squash` is refused by base-branch policy; `--auto` works. "Closes #N" didn't auto-close 4 issues, so the orchestrator closed them. Every PR appends to DECISIONS-LOG.md, which conflicts (#66); builders now rebase just before pushing. STATE.md updates went through 8 small orchestrator PRs (#65–#82).
7. **Planning gaps:** issue file lists keep missing DECISIONS-LOG.md, shared helpers and recording drivers. All were disclosed; none were defects.
